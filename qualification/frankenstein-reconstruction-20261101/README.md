## Memory accounting repair

The first B0 startup attempt exposed a source bug: `ram_room()` is already capped by the 80 GiB cgroup, but the original admission check also subtracted the host's 8 GiB reserve there. A 73.82 GiB payload plus that reserve could never pass an 80 GiB process envelope. B0 remains failed/HOLD.

The separately reviewed native-v3 fix keeps the envelopes separate: expert bytes must fit the process room and the 80 GiB expert ceiling, while physical host availability must independently retain 8 GiB. It does not raise the private cgroup fence, reduce experts, change arithmetic, lower context/output/effort or modify system-wide memory settings. The new C0 qualification used a fresh namespace and preserved the immutable B0 evidence. C0 loaded successfully, but subsequently breached the physical host margin during prose and had a native shutdown fault. The startup fix does not resolve those runtime limitations.

A progress message initially interpreted the roughly two-minute cancellation as a timeout. The saved response explicitly identifies physical RAM margin as the trigger; that interpretation was corrected. Timeouts were not extended.
