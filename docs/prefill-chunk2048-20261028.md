# Replicated chunk2048 prefill result

Increasing the native prefill chunk from 1024 to 2048, while retaining the active mode1 prefix optimization, reduced cold 32761-token prefill time by 30.53% and 30.38% in the two matched comparisons. All four arms are closed and independently audited. Chunk2048 was activated on the unchanged selected native at 10:30 UTC after separate source review and 43 activation controls on each host; public authentication and raw streaming READY/stop/DONE were verified.

These are two matched comparisons, not a statistical latency estimate.

Cache reuse, active and queued cancellation, cancellation during confirmed prefill, image ownership cleanup, and recovery checks passed in all four arms. The native executable, model, quantization, automatic 19/21 placement, TP1, mode1, Q8/check flags, 1M total context, 256K output allowance, native images, runtime projection, DSpark, 24 CPU threads, all CPU experts in RAM and stream0 stayed fixed.
