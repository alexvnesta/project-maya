# Q5_K and cache migration candidate

Status: implemented, built, GPU-checked and benchmarked as one bundle. Coding decode regressed3.66%; the candidate is not selected. Production is unchanged. See [the full comparison](Q5K_CACHE_BENCHMARK.md).

The dense Q5_K GEMV candidate shares the two exact 16-value activation sums across output rows in a CTA. It preserves the original quantized weights, separate floating minimum products, accumulation order, and original kernel fallback above 32 KiB dynamic shared memory. Enabling `DS4_Q5K_SHARED_SUMS=1` requires an original-versus-optimized GPU check on each device before requests: 72 jobs spanning columns 1–16, mixed batches, odd rows, padding, bias, and large-K fallback. This check is not whole-model equivalence.

`DS4_CACHE_REUSE_MIB=2` prices both transfers of an existing exclusive-tier expert swap against excess routing heat. Zero preserves the original admission predicate. The candidate adds no RAM tier, changes no weights, and retains all CPU expert weights in RAM. The price is a benchmark candidate, not an established optimum. Deferral counters count admission attempts, not cache misses or bytes saved.

The mapped table-input reuse guard follows the applicable hunk of [Maya PR550](https://github.com/mw00/project-maya/pull/550), handmade0octopus, head `06bd0c46b37acabaaa07d6e621c599cb097638a9` (MIT). It synchronizes and checks the previous stream use before overwriting the mapped host buffer. The other streamed-landing hunk targets methods absent from our pin and is not ported.

[PR460](https://github.com/mw00/project-maya/pull/460), shisuiki head `2e520c9acbb4bf182b25ec624cd2217213685e4e`, implements GLM inclusive RAM caching. A full inclusive copy would exceed our available RAM, so it is not ported. [Strata PR3779](https://github.com/Niko1221/Strata/pull/3779) primarily tunes Qwen SM80 paths, while [PR4302](https://github.com/Niko1221/Strata/pull/4302) introduces a helper-GPU cache on a different topology. Neither is a demonstrated drop-in DeepSeek Q5_K speedup for these two CMP170HX cards. Reviewed open PRs and recent fork branches did not reveal a directly applicable ready-made Q5_K implementation; this is not an exhaustive claim about every fork.

CPU controls exercise byte-price policy, separate integer half sums, a floating-rounding counterexample, shared-memory layout/fallback, and the actual extracted native table-publication method against delayed CPU reads and a sync-error negative control. They do not execute CUDA or qualify the native engine. First-run duplicated test output caused by inherited stdio buffering was preserved, then corrected with an explicit flush before the fork.

Benchmark intent: compare the selected production native against this combined candidate with the old rejected fusion/trim/drafter/copy bundle disabled. Preserve TP1, 1M allocation, Q8 batch/check, native images, runtime ablation, DSpark, 24 CPU threads, and prefill chunk 1024. Use the existing fixed short coding/prefill/tool/image panel and lifecycle gates, with unchanged request caps and effort. Natural stops, exact ownership, cleanup, public restoration, and manual generated-code adjudication are required. A first promising pair requires an order-reversed confirmation before promotion; capped, partial, wrong, or lifecycle-failed arms block advancement. No near-filled 1M or full 256K-output speed claim follows from a short panel.
